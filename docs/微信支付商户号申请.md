# 微信支付商户号申请

> 前置条件：已经拿到**个体工商户营业执照**（或企业执照）。如果没有，先看 [`个体工商户办理流程.md`](./个体工商户办理流程.md)。
> 目的：拿到 5 个支付参数填进 `backend/.env`，让 `POST /api/subscription/create_order` 真正能调起微信支付。
> 周期：1–5 个工作日（审核） + 半天（HTTPS 部署）。

---

## 一、要拿到的 5 个 .env 变量

走完整个流程，最终能填齐下面这 5 个：

```env
WECHAT_MCH_ID=               # 商户号（10 位数字），开户后自动分配
WECHAT_API_KEY_V3=           # APIv3 密钥（32 位字符串），自己设
WECHAT_MCH_SERIAL_NO=        # 商户 API 证书序列号
WECHAT_MCH_PRIVATE_KEY_PATH= # 商户 API 证书私钥 apiclient_key.pem 的绝对路径
WECHAT_PAY_NOTIFY_URL=       # 支付回调 URL，HTTPS，公网可达
```

下面每一节最后会标注「**👉 拿到了哪个变量**」。

## 二、注册商户号

1. 打开 https://pay.weixin.qq.com → 右上角「**商家接入**」→「**立即接入**」
2. 用**新邮箱**注册商户账号（这个账号管理你以后所有支付资金，**别用常用邮箱、密码独立、开二步验证**）
3. 验证邮箱后登录商户平台
4. 进入「**接入指引**」开始填资料

---

## 三、提交基本资料

按页面顺序填，关键字段如下：

| 表单字段 | 怎么填 |
|---|---|
| **主体类型** | 个体工商户 |
| **主体名称** | 与营业执照完全一致，例如「杭州市西湖区某某工作室」 |
| **统一社会信用代码** | 营业执照上的 18 位编号 |
| **营业执照照片** | 清晰、四角完整、不要反光 |
| **经营地址** | 与执照一致 |
| **法定代表人姓名 / 身份证号 / 身份证正反面照片** | 与执照一致；身份证拍清晰，避免阴影 |
| **法人手机号** | 必须本人实名号码（后续要扫脸 + 短信验证） |

提交后进入下一步。

| **小程序 AppID** | `wx145f0e364826d176` |

| 类目选择 | 后果 |

| ❌ 金融业 / 证券投资咨询 / 投资管理 | 要求增值电信业务许可证 + 金融牌照，办不下来 |

| ✅ **商务服务 → 软件服务** | 推荐，最容易过 |
| ✅ **信息服务 → 工具应用** | 备选 |
| ✅ **IT 服务 → 软件开发** | 备选 |

补充材料栏可以写：「本小程序为 AI 量化选股工具，向用户提供基于公开行情数据的策略筛选 / 回测服务，不构成投资建议，不收取代客理财费用，仅按订阅周期收取软件订阅费」。

## 六、结算账户

| 字段 | 怎么填（个体工商户） |
|---|---|
| **账户类型** | 「个体工商户经营者个人银行卡」或「对公账户」 |
| **开户银行 / 支行 / 卡号** | 法人本人储蓄卡（个体户允许） |

⚠️ 个体户**可以**用法人个人储蓄卡结算，省去开对公的麻烦。但 T+1 到账有单日/单月限额，超额要换对公。

## 七、超级管理员 + 签约

1. 填超级管理员（一般就是法人本人）：姓名、身份证、手机号
2. **法人扫脸验证**：微信扫描页面二维码 → 人脸识别
3. 签订《微信支付服务协议》
4. **提交审核**

## 八、等待审核（1–5 个工作日）

- 通过：邮件 + 短信通知，登录商户平台首页能看到 10 位**商户号 MCH_ID**
- 驳回：邮件会写具体原因（最常见是行业类目、经营范围、截图不符），改了重新提交

> **👉 拿到了：`WECHAT_MCH_ID`**

## 九、关联小程序 AppID（双向确认）

商户号审核通过 ≠ 能用，还得让商户号和小程序「拉手」。

### 9.1 商户平台侧发起

商户平台 → **产品中心** → **AppID 账号管理** → **关联 AppID** → 选「小程序」→ 输入 `wx145f0e364826d176` → 提交

### 9.2 小程序后台确认

⚠️ **必须由小程序管理员本人去做**，开发者权限不够。

- 登录 https://mp.weixin.qq.com（用注册小程序时的那个微信扫码）
- 左侧 **功能** → **微信支付**（或 **设置 → 第三方设置 → 关联微信支付商户号**）
- 看到刚才发起的关联请求 → **同意**

只有这两步都做完，JSAPI 下单时 `appid` 才不会被微信判定为 "appid mismatch"。

## 十、开通 JSAPI 支付产品

商户平台 → **产品中心** → 找到 **JSAPI 支付** → **申请开通** → 通常即时通过

开通后才能调 `https://api.mch.weixin.qq.com/v3/pay/transactions/jsapi`（项目 `backend/wechat_pay.py:35` 用的就是这个）。

## 十一、设置 APIv3 密钥

⚠️ 这一步**设完只显示一次**，丢了只能重置。

1. 商户平台 → **账户中心** → **API 安全**
2. 找到「**APIv3 密钥**」→ **设置密钥**
3. **自己生成一个 32 位的字符串**（推荐密码管理器随机生成，包含大小写字母和数字）
4. 短信验证 + 操作员密码
5. **立刻复制保存到本地密码管理器**

填进 .env：

```env
WECHAT_API_KEY_V3=你设的那 32 位字符串
```

> **👉 拿到了：`WECHAT_API_KEY_V3`**

## 十二、申请 API 证书（含私钥）

商户平台 → **账户中心** → **API 安全** → **申请 API 证书** → 按指引操作。

有两种方式，选其一：

### 方式 A：用「微信支付商户助手」工具（推荐）

1. 下载工具：商户平台页面上有链接，Windows / Mac 都有
2. 工具会**本地生成**一对 RSA 密钥（私钥不离开你电脑）
3. 工具自动把 CSR 提交到商户平台
4. 下载 3 个文件到本地：
   - `apiclient_cert.pem` —— 证书公钥
   - `apiclient_key.pem` —— **私钥（最重要，绝对不能泄漏，绝对不能进 git）**
   - `apiclient_cert.p12` —— PKCS#12 格式（一般用不到）

### 方式 B：用 OpenSSL 命令行

```bash
# 1. 本地生成私钥
openssl genrsa -out apiclient_key.pem 2048
# 2. 用私钥生成 CSR（按提示填，CN 填商户号）
openssl req -new -key apiclient_key.pem -out apiclient.csr
# 3. 把 apiclient.csr 内容粘到商户平台 → 下载 apiclient_cert.pem
```

### 把证书放进项目

**⚠️ 不要放进 git 仓库**。建议放在项目外的目录：

```
D:\project\stock_app\certs\apiclient_key.pem
D:\project\stock_app\certs\apiclient_cert.pem
```

然后在 `.gitignore` 加一行：

```
certs/
```

填进 .env：

```env
WECHAT_MCH_PRIVATE_KEY_PATH=D:/project/stock_app/certs/apiclient_key.pem
```

> **👉 拿到了：`WECHAT_MCH_PRIVATE_KEY_PATH`**

## 十三、查看证书序列号

证书申请成功后，商户平台 → **账户中心** → **API 安全** → **API 证书** 列表里能看到一串十六进制字符串，那就是序列号。

也可以本地用 OpenSSL 查：

```bash
openssl x509 -in apiclient_cert.pem -noout -serial
# 输出: serial=4A7B6C5D...（去掉前面的 serial= 就是）
```

填进 .env：

```env
WECHAT_MCH_SERIAL_NO=4A7B6C5D...
```

> **👉 拿到了：`WECHAT_MCH_SERIAL_NO`**

## 十四、支付回调 URL（最容易卡的一步）

### 14.1 微信的硬性要求

- **必须是 HTTPS**（HTTP 直接拒绝）
- **必须公网可达**（内网/localhost 不行）
- **必须能正常响应**微信 POST 过来的回调（不能 404、不能 502）
- **必须能保持稳定**（频繁不可达微信会暂停推送）

### 14.2 你当前的情况

后端目前跑在 `121.40.124.210:8000`（HTTP，IP 直连）。**不能直接用**。

### 14.3 解决方案（选一种）

| 方案 | 适用 | 难度 |
|---|---|---|
| **A. 域名 + Nginx + Let's Encrypt** | 你已有域名，或愿意备案一个 | 中等，免费 |
| **B. 云厂商一键 SSL 代理** | 阿里云/腾讯云 SLB / CDN 反代回源到 8000 | 简单，每月几十块 |
| **C. Cloudflare Tunnel** | 只做测试 / 个人项目；不需要备案 | 简单，免费；但国内访问慢 |
| **D. 用 frp / ngrok 做内网穿透** | **只能开发自测**，绝不能用于生产 | 简单，免费/便宜 |

⚠️ **国内域名要做 ICP 备案**（20 天左右）。如果还没备案，建议先用 Cloudflare Tunnel 临时顶住，等备案下来再切。

### 14.4 推荐结构

```
微信支付服务器
    │ HTTPS POST
    ▼
你的域名 pay.yourdomain.com (HTTPS, 443)
    │ Nginx 反向代理
    ▼
121.40.124.210:8000 /api/wechat_pay/notify (HTTP)
    │
    ▼
FastAPI 处理回调
```

### 14.5 .env 配置

```env
WECHAT_PAY_NOTIFY_URL=https://pay.yourdomain.com/api/wechat_pay/notify
```

⚠️ 项目里目前还没看到 `/api/wechat_pay/notify` 这个回调接口的实现（`backend/wechat_pay.py` 里有 `verify_callback_signature` 和 `decrypt_callback_data` 两个工具函数，但 `main.py` 里没有挂对应路由）。**真上线前必须在 `main.py` 里加这个回调接口**，否则微信通知会 404、订单永远停在 pending。

> **👉 拿到了：`WECHAT_PAY_NOTIFY_URL`**

## 十七、可能踩的坑

| 现象 | 原因 |
|---|---|
| 调用统一下单返回 `appid mismatch` | 第九步「关联 AppID」没有在小程序后台完成确认 |
| 返回 `mch_id not exists` | 商户号填错；或还没审核通过 |
| 返回 `signature error` | 私钥文件路径不对、私钥和证书序列号对不上、或私钥被换行符破坏 |
| 返回 `notify_url invalid` | 回调 URL 不是 HTTPS、域名解析失败、或公网不通 |
| `wx.requestPayment` 报「商户号未授权该 appid」 | 同第一行，关联没做完 |
| 用户支付成功了但订单一直 pending | 回调接口没实现 / 回调签名验证失败 / 回调 URL 不可达 |
| 支付完小程序提示成功，但你后台没收到钱 | 沙箱/测试号 / 商户号和小程序不匹配 / 结算账户没认证完 |

## 十八、安全提醒（务必看）

| 资产 | 风险 | 怎么做 |
|---|---|---|
| 商户平台密码 | 被改密码 → 改结算账户 → 资金被卷走 | 独立邮箱 + 独立密码 + 二步验证 |
| APIv3 密钥 | 泄漏 → 别人能解密你的回调、伪造回调 | 只放 .env，**绝不进 git**；定期轮换 |
| 商户私钥 apiclient_key.pem | 泄漏 → 别人能以你的名义调微信 API | 文件 chmod 600；**绝不进 git**；存到项目外 |
| 法人手机号 | 接收所有验证短信 | 不要轻易换号 |
| 结算账户 | 资金落地的最后一公里 | 定期对账，开启短信通知 |
